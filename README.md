## Project Overview

TheLastUpload is a 2D cyberpunk, story-driven puzzle-adventure game set inside a corrupted digital simulation.

The world appears to be a controlled digital environment maintained by an advanced system. Information is manipulated, memories are fragmented, and the boundary between reality and artificial reconstruction is deliberately obscured.

The player enters this environment to investigate irregularities, access restricted systems, solve logic-based puzzles, and recover lost memory fragments.

As the investigation progresses, the player discovers that the simulation may be concealing information that the system was designed to suppress.

### Core Objective

**Break the simulation and recover the last hidden memory.**

### Game Pillars

- **Exploration:** Navigate the cyberpunk world and discover hidden information.
- **Investigation:** Examine terminals, environmental clues, and corrupted data.
- **Puzzle-Solving:** Solve logic challenges to access restricted systems.
- **Reality Manipulation:** Change elements of the environment through puzzle solutions.
- **Narrative Discovery:** Reconstruct the truth through recovered memories and digital records.

### Project Vision

TheLastUpload combines accessible 2D movement with meaningful puzzle interactions and a mystery-driven narrative.

Every area should give players opportunities to investigate the world, discover inconsistencies, and understand the consequences of interacting with the simulation.

## Problem Statement

### The Challenge: A World Where Information Cannot Be Trusted

In a world controlled by digital systems, information can be altered, hidden, duplicated, or presented in misleading ways.

TheLastUpload explores this idea through a fictional simulation in which the player cannot immediately trust the environment or the information provided by its systems.

The central challenge is to discover the truth while operating inside the very system that conceals it.

### Key Questions

- Can a digital system accurately preserve a person's memories?
- How can the player distinguish genuine information from manipulated data?
- What happens when a system controls both the world and the information available to its inhabitants?
- Can the rules of a simulation be used against the system that created them?
- If a memory can be copied or altered, what makes it authentic?

### Gameplay Challenges

| Challenge | Proposed Solution |

| Restricted Access | Solve terminal puzzles to unlock systems and routes. |
| Hidden Information | Discover environmental clues and memory fragments. |
| Corrupted Data | Investigate anomalies in the simulation. |
| Environmental Obstacles | Activate mechanisms and open blocked paths. |
| Narrative Uncertainty | Reconstruct the story through recovered information. |
| Player Progression | Unlock new areas by completing objectives. |

## Our Solution

TheLastUpload turns digital deception into an interactive experience.

Instead of presenting the story through exposition alone, the game encourages players to investigate the simulation directly.

### Five Core Components

#### 1. Two-Dimensional Exploration

Navigate a side-view environment using the 2D player character. Movement, jumping where supported, and environmental obstacles form the foundation of exploration.

#### 2. Terminal-Based Hacking

Interact with terminals to access fictional digital systems, solve logic puzzles, and uncover restricted information.

#### 3. Environment Manipulation

Puzzle completion can change the world by opening barriers, activating platforms, restoring power, or revealing hidden passages.

#### 4. Memory Reconstruction

Collect memory fragments to uncover pieces of the narrative and gradually reconstruct the truth.

#### 5. Story-Driven Progression

Use discoveries and completed objectives to access new areas and advance the investigation.

### Design Principle

**The player does not merely escape the simulation. The player learns to manipulate it.**

## Gameplay Systems

### Player Movement System

The movement system handles horizontal movement, jumping where supported, and interaction with the physics environment.

A typical Unity 2D implementation may use a `Rigidbody2D` and suitable `Collider2D` components.

Important considerations:

- Consistent movement speed.
- Ground detection for jumping.
- Collision with platforms and walls.
- Appropriate gravity and jump force.
- Stable behavior across frame rates.
- Correct handling of level boundaries.

### Interaction System

A typical interaction sequence is:

1. The player approaches an interactive object.
2. The game detects the player within interaction range.
3. An interaction prompt appears.
4. The player presses the interaction key.
5. The object opens a puzzle, displays information, or performs an action.
6. The game updates the relevant state.

Interaction detection can use trigger colliders or raycasting.

### Terminal System

A terminal may contain:

- A hacking puzzle.
- A restricted data record.
- A story message.
- An environmental control.
- A memory-related clue.

Different terminals should be configurable without requiring a completely separate interaction system for each object.

### Puzzle System

The puzzle system receives player input, evaluates the solution, and returns a result.

A successful solution can unlock a door, activate a mechanism, reveal information, or mark an objective complete.

An unsuccessful attempt should provide understandable feedback and allow another attempt when appropriate.

### Environment State System

This system manages changes triggered by gameplay, such as:

- Locked and unlocked barriers.
- Inactive and active platforms.
- Disabled and restored machinery.
- Hidden and revealed objects.
- Unavailable and accessible routes.

### Memory Collection System

When a memory fragment is collected, the game should:

1. Detect the collection.
2. Prevent duplicate collection when appropriate.
3. Update progress.
4. Display feedback.
5. Unlock associated narrative content or progression.

### Game State System

The game may use separate states for the main menu, gameplay, pause screen, puzzle interface, and completion.

State changes should be handled consistently so that controls, UI, and gameplay systems do not conflict.

## Puzzle Design

### Puzzle Objective

Puzzles represent digital restrictions within the simulation. The player interprets available information and provides a valid solution to access a system or change the environment.

### Suggested Puzzle Types

**Logic Sequence Puzzle**

Identify a missing element in a sequence using clues provided by the terminal.

**Code Identification Puzzle**

Discover environmental clues and use them to enter a valid access code.

**Memory Reconstruction Puzzle**

Arrange or connect information fragments to reconstruct a memory.

**System Configuration Puzzle**

Activate or arrange system components in the correct order to restore functionality.

> These are proposed puzzle types. Include them in the playable build only if implemented.

### Puzzle Feedback

| Player Action | Expected Feedback |
|---|---|
| Open terminal | Display the puzzle interface. |
| Submit a correct answer | Show success feedback and trigger the assigned result. |
| Submit an incorrect answer | Explain the error and allow another attempt. |
| Complete the puzzle | Unlock the associated route, record, or mechanism. |
| Exit the puzzle | Return control to the gameplay environment. |

### Puzzle-to-Environment Connection

1. The player finds a terminal beside a locked door.
2. The player interacts with the terminal.
3. A code puzzle appears.
4. The player solves the puzzle.
5. The terminal confirms access.
6. The door changes to its unlocked state.
7. The player continues exploring.

## Technical Implementation

The project is developed in Unity using a 2D gameplay approach.

The existing player character is the foundation for movement and exploration.

The setup may include:

- Sprite Renderer.
